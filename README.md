# 红石计算机指令集说明 (README)

## 概述

这套红石计算机采用**双 Bank ROM 架构**，程序空间分为 Bank 0 与 Bank 1。每个 Bank 拥有独立的 **5 位指令寻址总线**，可寻址 0~31 共 32 个指令单元。

- **Bank 0**：通常存放主程序。
- **Bank 1**：可存放副程序或中断服务程序，具体用途由用户决定。
- **数据存储器 RAM**：地址宽度 3 位，共 8 个存储单元（000~111）。
- **累加器 ACC（寄存器 A）** 与每个 RAM 单元的数据宽度均为 **3 位**，数值范围 0~7，所有算术运算均按 **模 8** 自动回绕溢出。

---

## 存储架构详解

### RAM 地址分配

| 地址 | 用途 |
|------|------|
| 000 ~ 100 | 普通数据存储单元，可自由读写 |
| **101** | **ALU 的 B 寄存器**（只写不可读），通过 `LDDIR` 写入 |
| **110** | **南桥 MMIO 地址端口**（只写不可读） |
| **111** | **南桥 MMIO 数据端口**（只写不可读） |

> ⚠️ **重要**：普通访存指令 `LW` **不能读取** 101、110、111 这三个单元，它们各自有专用的读取路径。

### Bank 切换与特殊指令

- **YIELD**（`01110000`）：只能在 Bank 0 中使用，触发切换到 Bank 1。
- **FINISH**（`01101000`）：只能在 Bank 1 中使用，触发切回 Bank 0。
- 这两个指令并非强制，若不需要上下文切换，可全部用作逻辑指令。

## 指令集详解

### 1. 基础数据传输与算术指令

| 指令 | 编码格式 | 操作说明 |
|------|----------|----------|
| **LDDI** | `00001XXX` | 将 3 位立即数 XXX 加载到寄存器 A |
| **ADDI** | `00010XXX` | A = A + XXX（模 8 回绕） |
| **LW** | `00011XXX` | 读取内存地址 XXX 中的数据到 A（XXX 不能是 101/110/111） |
| **SW** | `00100XXX` | 将 A 的值写入内存地址 XXX（可写入所有单元，含 110/111） |
| **LDDIR** | `01001XXX` | 将立即数 XXX 写入内存单元 101（B 寄存器），不改变 A |
| **ALU** | `01000OPQ` | OPQ 决定运算类型（见下表） |

#### ALU 操作码表（OPQ）

| OPQ | 运算 | 结果 |
|-----|------|------|
| `001` | 加法 | A = A + B（模 8） |
| `010` | 小于比较 | A < B ? A=0 : A=1 |
| `011` | 减法 | A = A - B（模 8） |
| `100` | 赋值 | A = B |
| `101` | 按位与 | A = A & B |
| `110` | 右移 | A = B >> 1（整除 2） |

> **注意**：使用 ALU 前**必须**先通过 `LDDIR` 或其它方式设置好 B 寄存器，否则 B 的内容不确定。

---

### 2. 内存间接寻址指令（指针访问）

| 指令 | 编码 | 操作 |
|------|------|------|
| **LDR** | `00110000` | 以内存单元 101 的值为地址，读取该地址的数据到 A |
| **SDR** | `00111000` | 以内存单元 101 的值为地址，将 A 的值写入该地址 |

> ⚠️ 使用时务必确保 101 单元中的地址值在 0~7 之间，避免访问只写单元或产生意外行为。

---

### 3. 控制流指令

| 指令 | 编码 | 操作 |
|------|------|------|
| **JMP** | `111XXXXX` | 无条件跳转到 5 位地址 XXXXX |
| **BEQ** | `110XXXXX` | 若 A == 0 则跳转到 XXXXX，否则顺序执行 |
| **CALL** | `101XXXXX` | 跳转到子程序，硬件自动将 PC 和 A 压入调用栈 |
| **RET** | `10000000` | 从调用栈弹出 PC 和 A，返回调用点 |
| **HALT** | `00101000` | 停止程序执行 |

> ⚠️ 硬件调用栈最大深度为 **3 层**，CALL 嵌套**绝对不能超过 3 层**，否则会破坏栈数据。

---

### 4. 数据栈指令（PUSH / POP）

- 编码：`0110000B`，最低位 B 决定操作：
  - **B = 0**：`PUSH` – 将 A 的值压入硬件数据栈
  - **B = 1**：`POP` – 从数据栈弹出值到 A

> ⚠️ 使用时必须保证在同一个函数或代码块中 PUSH 与 POP 次数**完全相等**（栈平衡），否则会导致栈溢出或数据错乱。

---

### 5. DMA 指令

- 编码：`01011XXB`
- 用于在内存单元 **001~100** 与外部存储之间批量传输数据（4 个单元）。
- **XX 字段**选择目标扇区：
  - `01`：硬盘扇区 1
  - `10`：硬盘扇区 2
  - `00`：高速互联接口 RSLINK
- **B 字段**传输方向：
  - `0`：将内存 001~100 的数据写入目标
  - `1`：从目标读取数据到内存 001~100

> ⚠️ **DMA 指令后必须紧跟一条 `NOP`（`00000000`）** 作为硬件延迟槽，否则数据可能无法正确锁存。

#### RSLINK 特别说明

- `DMA 01011000`：从接口读取数据到内存
- `DMA 01011001`：将数据写入接口并自动发送
- 发送或读取完成后，接口内容自动清空，无需手动清标志。

---

### 6. 外设交互

#### 键盘 MMIO（内存映射 I/O）

使用专用读取指令访问键盘，**不占用**南桥地址。

| 指令 | 编码 | 操作 |
|------|------|------|
| `LW 110` | `00011110` | 读取键盘标志位（1=有按键，0=无） |
| `LW 111` | `00011111` | 读取键盘数据缓冲区中的 3 位键值，**硬件自动清除标志位** |

**标准轮询流程**：
1. `LW 110` 读取标志位
2. `BEQ` 跳转回循环等待（若 A=0）
3. 标志位为 1 时，执行 `LW 111` 获取键值

---

#### 南桥 MMIO

南桥通过内存单元 110（地址选择）和 111（数据输入）访问。

##### 发送数据流程
1. 将模块地址写入内存单元 110（使用 `SW`）
2. 将 3 位数据写入内存单元 111
3. 执行 **MMIO 激活指令** `01111000`，硬件完成发送

##### 读取数据流程
1. 将模块地址写入内存单元 110
2. 执行 `LW 101`（读取南桥输出值到 A）
3. 对应模块的标志位会自动清空

##### 南桥模块地址表

| 地址 | 模块功能 |
|------|----------|
| `000` | 有线网卡发送模块 |
| `001` | 有线网卡接收输出模块 |
| `010` | 有线网卡接收标志位 |
| `011` | USB 输入 1 模块 |
| `100` | USB 输入 2 / RSLINK 标志位 |
| `101` | 无线网卡发送模块 |
| `110` | 无线网卡接收输出模块 |
| `111` | 无线网卡接收标志位 |

> 读取接收输出模块后，对应标志位自动清空。

**示例：读取有线网卡数据**
1. 将 `010` 写入 `110`，执行 `LW 101` 读取标志位
2. 若 A=0，`BEQ` 跳回轮询
3. 标志位为 1 时，将 `001` 写入 `110`，执行 `LW 101` 读取数据

---

#### 显示指令（DISPLAY）

- 编码：`01010JKL`
- **显示 3 位数**：执行 `01010100`（J=1，K=0，L=0），A 的值立即输出到屏幕
- **显示 6 位数**（分两次操作）：
  1. 第一次：`01010001`（J=0，L=1），暂存 A 的低 3 位作为前半部分（不输出）
  2. 第二次：`01010111`（J=1，K=1，L=1），拼接前半部分和当前 A 的值（后半部分）并输出
  - 两次 L 位都必须为 1，第二次 K 必须为 1，第一次 K 可任意。

## 上下文切换机制（YIELD / FINISH + 中断）

### 触发方式

- **主动 YIELD**：在 Bank 0 中执行 `YIELD` 指令
- **键盘中断**：抢占式中断，优先级高于 YIELD，可在 Bank 0 或 Bank 1 执行期间触发

### 切换程序存储区

不占用 Bank 0/1 地址空间，而是存放在**独立的指令存储器**中。分为两组（键盘中断组和主动 YIELD 组），每组包含 **8 条指令槽位**：

- **前 4 条（程序 A）**：负责 Bank 0 → Bank 1，**最后一条必须是 `CALL`**
- **后 4 条（程序 B）**：负责 Bank 1 → Bank 0，**最后一条必须是 `RET`**
- 其余槽位可留空（等价于 `NOP`），硬件会完整执行所有槽位。

### 现场保存与恢复

- 执行程序 A 时，主 PC 被硬件锁存（保持被中断程序的下一条指令地址）。
- 程序 A 最后的 `CALL` 执行时，硬件将**锁存的 PC** 和**当前 A 的值**压入调用栈。
- 程序 B 最后的 `RET` 弹出 PC 和 A，恢复被中断程序执行。

### 使用场景与编写建议

#### 场景 1：仅作逻辑空间扩展（无数据保存需求）
- 程序 A：前 3 条留空（NOP），最后一条写 `CALL 目标地址`
- 程序 B：前 3 条留空，最后一条写 `RET`
- 即可实现 Bank 0/1 的无缝切换。

#### 场景 2：Bank 1 作为独立副程序，需保护现场数据
- 程序 A 中应包含 **DMA 指令**，将内存 001~100 保存到硬盘扇区（注意 DMA 后紧跟 NOP）
- 程序 B 中应包含 **DMA 指令**，从硬盘扇区恢复数据
- 由于程序 A/B 只有 4 个槽位，必须精打细算，确保不超槽位并满足延迟槽要求。

### 中断嵌套

- 若键盘中断发生在 Bank 1 程序执行期间，会形成中断嵌套。
- 键盘服务程序结束后，先返回 Bank 1 继续运行，待 Bank 1 执行 `FINISH` 后再返回 Bank 0 主程序。
- **上下文切换程序执行期间不会响应新的中断**，因此切换过程不会被再次打断。

### 重要限制

- 调用栈总深度（切换程序的 CALL + 内部嵌套 CALL）**仍不能超过 3 层**。
- Bank 1 程序必须保证内部 `CALL`/`RET`、`PUSH`/`POP` 次数完全平衡。
- Bank 1 程序应一次性执行完毕并通过 `FINISH` 返回，**不要在内部再次主动触发 YIELD**。

---

## 编程注意事项（总结）

| 要点 | 说明 |
|------|------|
| `LW` 限制 | 不能读取 101、110、111 单元 |
| 间接寻址 | 必须确保 101 单元的值有效（0~7） |
| DMA | 后必须紧跟 `NOP` 作为延迟槽 |
| CALL 嵌套 | 不得超过 3 层（含上下文切换中的 CALL） |
| 数据栈 | PUSH/POP 必须成对出现，保持平衡 |
| 键盘读取 | 自动清除标志位，无需手动清零 |
| 南桥读取 | 先写地址到 110，再 `LW 101` 读取 |
| 6 位显示 | 必须分两次操作，并遵守 L/K 位的规则 |
| 上下文切换程序 | 必须正确编写 CALL/RET，并根据需要决定是否使用 DMA 保存内存数据 |
